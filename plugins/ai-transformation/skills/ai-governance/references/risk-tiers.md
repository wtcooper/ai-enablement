# Risk tiers and human review (step 3)

Read this on entering step 3. It sets risk tiers by what happens if the output is wrong and who relies on it, then
writes the human review each tier needs, mapped to the shared agentic patterns and the ladder. Source keys in brackets
are listed in §9. Tier ids are in `references/schemas/policy.md` §3.4.

## 1. Goal and exit criteria

**Goal.** Review effort sized to consequence. NIST GOVERN 1.3 asks for risk-management effort sized to the
organization's risk tolerance [NIST-RMF-2023]. The review standard does not drop because AI helped: firms investing in
AI tools told PCAOB staff that AI is expected to augment, not replace, people, and some said the engagement team member
remains responsible and reviewers apply the same diligence as when AI was not involved [PCAOB-GENAI-2024, pp.4-5]. The tier sets how much
extra checking the first-line user does, who else reviews, and what is recorded.

**Exit when all of these are true:**
- **Four tiers** (or the firm's own), each with typical uses, reviewer, what the reviewer checks, the record needed
  (detail in step 4) and the autonomy allowed.
- **A list of uses not permitted until approved.**
- **A rule for autonomy:** how moving up the ladder changes the tier.
- **A pattern map** for the patterns the firm uses or plans (§5).
- **`max_risk_tier`** set on each catalog entry.

## 2. How to run it

1. **Ask for the worst realistic failure** in this practice (R1). It anchors the top tier in the user's world.
2. **Offer the default tiers** (§5) and sort the user's real uses into them, one use at a time.
3. **For each tier, ask who reviews and what exactly they check** (R3). "Review" with no object is not a control.
4. **Set the autonomy rule** with the ladder (§5). Read `../../transformation-advisor/references/library/index.md`
   §1 and §3 if you need the ladder and pattern definitions.
5. **List uses not permitted until approved.** In the PCAOB outreach, some firms allowed generative AI for
   administrative documents, initial drafts and internal research, and some did not allow it when performing audit or
   attest procedures [PCAOB-GENAI-2024, p.4].
6. **Replay an incident** against the tiers (move 3): would the controls have caught it?
7. **Play back, write section 4 of the policy, set `max_risk_tier` on catalog entries, and draft the review lines of
   the guardrails.**

## 3. Question bank

| # | Question | Scope |
|---|---|---|
| R1 | What is the worst realistic failure here: a confidentiality breach, a wrong filing, a fabricated authority, an independence breach? | [U] |
| R2 | Which outputs leave the firm, and who outside relies on them? | [all] |
| R3 | For this kind of work, who checks the AI-assisted output today, and what exactly do they check? | [T] |
| R4 | If this output reached the client unverified, which of our controls would catch it? | [T/U] |
| R5 | Where would an agent or automation act without a person watching, and what could it change? | [U/O] |

More, as needed:
- Which uses need consent, an independence check or a high-tier review before any pilot? [U]
- If review moves (for example machine-checked citations), what does the reviewer still own personally? [U]
- What would we show a regulator, client or court that review happened? [T/U]

## 4. Expert moves

1. **Tier by consequence of error and audience, and write the review step into the tier.** Designing tiers. Reveals
   which uses need verified sources, a second reviewer or prohibition [NIST-RMF-2023; PCAOB-GENAI-2024, p.4]. Tier
   thresholds are an advisor default; present them as a starting point.
2. **Set the standard as "same diligence as if AI were not involved", with the user accountable.** Review policy.
   Reveals whether supervisors are being asked to relax review [PCAOB-GENAI-2024, pp.4-5]; ABA Opinion 512 says that,
   whatever level of review the lawyer selects, the lawyer is fully responsible for the work [ABA-OP512-2024].
3. **Replay incidents as scenario tests.** Review-design workshops. Reveals controls that exist only on paper. Public
   examples: counsel and firm sanctioned $5,000 for submitting non-existent cases generated by a chatbot
   [SDNY-AVIANCA-2023]; a consultancy agreed to repay the final instalment of a government report contract after
   errors including incorrect references, having disclosed generative AI use, while not saying AI caused the errors
   [GUARDIAN-DELOITTE-2025].
4. **Test before you trust: challenge the vendor model on your own samples.** Before a tool enters tier 3 or 4 work.
   Banking supervisors' model-risk guidance applies validation to vendor models and expects "effective challenge"
   by objective, informed parties [FRB-SR117-2011]. Re-test when the vendor changes the model; NIST lists underlying
   model versions as an inventory field [NIST-600-1-2024, GV-1.6-003].
5. **For tier-4 uses, run an internal-audit frame before launch: scope, map, collect artifacts, test, reflect.**
   High-tier uses. Reveals missing evidence; this is the SMACTR framework for internal algorithmic audit [RAJI-2020].
6. **Give agents least privilege and a list of actions that always pause for a person.** Background agents and
   managed agent runtimes. OWASP lists excessive agency among LLM application risks [OWASP-LLM-2025]; the advisor's
   control table covers autonomy tiers, escalation and rubber-stamp watch
   (`../../transformation-advisor/references/method/plan-and-control.md` §3.4).

## 5. Checklists and decision rules

**Default tiers (advisor default; adjust with the user):**

| Tier | Typical uses | Reviewer and check | Record (step 4) |
|---|---|---|---|
| `tier-1` Internal, low consequence | Admin, internal drafts, brainstorming on public or firm-internal data | The user checks before use | Tool logs only |
| `tier-2` Informs professional work | Research notes, analysis, first drafts a professional then uses; supervision unchanged | The user verifies sources and figures; the normal reviewer reviews the work as usual | Light: tool used and what was checked |
| `tier-3` Client-facing or relied on | Deliverables, advice, client communications, anything leaving the firm | A named qualified reviewer checks facts, figures and every citation against its source before release | Prompt or input description, how verified, who reviewed [CPAI-2026] |
| `tier-4` Regulated or high-impact | Attest procedures and evidence, signed returns and filings, court submissions, decisions about people, agents acting on client data or outside the firm | Use-case approval record before use; test results on firm samples; written reviewer instructions; regime steps (step 5) | Tier 3 plus tool and model version, configuration, why use was appropriate, approval, how output informed the conclusion |

**Ladder rule (advisor default):** each move up the ladder (assist → augment → automate → delegate) raises the tier by
at least one level until test evidence supports lowering it. `delegate` is always `tier-4` and must pass the five
delegation gates in `../../transformation-advisor/references/method/onboarding.md` §5.

**Pattern map.** Checkpoints and failure modes come from the shared library
(`../../transformation-advisor/references/library/index.md` §3); minimum tiers are an advisor default when the output
leaves the firm or feeds a regulated step.

| Pattern | Usual ladder | Minimum tier | What the reviewer must own | Failure to watch |
|---|---|---|---|---|
| `research-brief` | assist → augment | tier-2; tier-3 if cited to a client or court | Reads the sources behind key claims | Invented or misread citations |
| `draft-review-loop` | assist → augment | tier-3 for client deliverables | Sign-off before anything leaves the team | Review becomes a rubber stamp |
| `grounded-knowledge-assistant` | assist | tier-2 | Content owners keep the knowledge current | Stale or unapproved content |
| `document-to-decision` | augment → automate | tier-3; tier-4 for attest or filing decisions | Approves decisions above a threshold | Extraction errors treated as fact |
| `full-population-testing` | automate | tier-4 in attest work | Investigates and concludes on exceptions | False positives that swamp reviewers |
| `intake-triage` | augment → automate | tier-2; tier-3 if it routes client requests | Spot checks of routing; owns the exception queue | Misrouted urgent items |
| `reconcile-exceptions` | automate | tier-3 | Clears unresolved breaks | Forced matches that hide real breaks |
| `service-agent-escalation` | automate | tier-3 | Escalation rules; samples conversations | Confident wrong answers |
| `monitor-diagnose-act` | augment → automate | tier-3; tier-4 if it acts | Approves actions that are hard to reverse | Unsafe automatic actions |
| `bulk-transformation` | automate | tier-3 | Sampled checks; sign-off before cutover | Silent errors at scale |
| `end-to-end-case-agent` | delegate | tier-4 | Checkpoints at key decisions and before anything irreversible | Errors compounding across steps |

**Runtime-class notes (advisor default):**
- `personal-assistant`: the exposure is what the user pastes; controls are data-class training, business-tier
  accounts and retention settings.
- `shared-team-skills`: version and own each skill; re-test after model changes.
- `workflow-automation`: log inputs and outputs per run; name the human checkpoint.
- `background-agent`: least privilege, approval for sensitive actions, activity logs, a way to stop it, an inventory
  entry.
- `managed-agent-runtime`: assess the platform (tenancy, logging, data location, change notice) and each agent.

**Decision rules**
- Uses for recruitment, decisions on terms of work, task allocation based on behaviour or personal traits, or
  monitoring and evaluating staff are `tier-4` (advisor default): the EU AI Act's Annex III lists them
  [AIACT-EXPL-2026, Annex III point 4], with high-risk obligations applying from 2 December 2027 under
  Regulation (EU) 2026/1744 [EU-OMNIBUS-2026]. Re-verify dates before advising.
- Irreversible, sensitive or high-value actions by an agent always pause for a person (plan-and-control §3.4).
- A tier is set for the use, not the tool: one tool can serve tier-1 and tier-3 uses with different reviews.

## 6. Common traps

| Trap | Evidence | How to avoid |
|---|---|---|
| Review that changes nothing | In the University of Melbourne and KPMG survey of employees in 47 countries, 66% reported relying on AI output without evaluating it and 56% reported mistakes from AI use (self-reported) [KPMG-MELB-2025, p.75] | Say what the reviewer verifies; check every citation at source; record who reviewed |
| Relaxing supervision because AI "did the first pass" | Some firms told PCAOB staff their supervision and review policies had not changed [PCAOB-GENAI-2024, pp.4-5] | Write "same diligence" into every tier |
| Tiering by tool, not by use | One tool serves many uses | Tier each use; set `max_risk_tier` on the entry as a ceiling |
| Agents outside the tiers | In an EY-commissioned survey of 202 senior AI executives at large US public companies, 26% of those whose organizations use agentic AI said they could not detect unauthorized agents (self-reported) [EY-AIGOV-2026] | Agents acting on client data or outside the firm are tier-4 (§5); every agent enters the inventory like a user |

## 7. Worked example

Illustrative, not a case study. An audit practice wants staff to use an assistant for technical research and memo
drafts, mirroring practice some firms described to PCAOB staff [PCAOB-GENAI-2024, p.4].

- **Lane 1 (`tier-2`):** research and drafting on firm-internal data, or client-confidential data only in an entry
  approved for it; the user checks every cited standard at source; supervision unchanged.
- **Lane 2 (`tier-4`):** performing audit procedures with AI is not permitted until a tool has an approval record,
  test results on firm samples and reviewer instructions; a firm-built tool also needs the documentation in step 4.
- **Independence:** if the firm builds or hosts an AI tool for an attest client, step 5 runs the nonattest-services
  analysis [JOFA-2026].
- **Replay (R4):** a fabricated citation in a memo would be caught only if the reviewer checks the source; the tier-2
  rule now says so.
