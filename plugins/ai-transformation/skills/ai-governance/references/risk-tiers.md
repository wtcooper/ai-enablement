# Risk tiers and human review (step 3)

Read this on entering step 3. It sets risk tiers by the consequence of a wrong output and who relies on it, then the
human review each tier needs. Sources are in §8; tier ids in `references/schemas/policy.md` §3.4.

## 1. Goal and exit criteria

**Goal.** Review effort sized to consequence; NIST GOVERN 1.3 asks for risk-management effort sized to risk
tolerance [NIST-RMF-2023]. The tier sets the user's checking, who else reviews, and what is recorded.

**Exit when all of these are true:**
- **Four tiers** (or the firm's own), each with uses, reviewer, check, record (step 4) and autonomy allowed.
- **Uses not permitted until approved**, each with its alternative; **an autonomy rule**; **a pattern map**.
- **`max_risk_tier`** set on each catalog entry.

## 2. How to run it

1. **Ask for the worst realistic failure** (R1) to anchor the top tier; sort real uses into the default tiers (§5).
2. **For each tier, ask who reviews and what exactly they check** (R3). "Review" with no object is not a control.
3. **Set the autonomy rule** with the ladder (§5; ladder and patterns in the library index §1 and §3).
4. **List uses not permitted until approved.** Each names its alternative: an approved catalog entry, a permitted
   lower-tier use, or the request path (rule 12). Some audit firms told PCAOB staff they did not allow generative AI
   when performing audit or attest procedures [PCAOB-GENAI-2024, p.4].
5. **Replay an incident** against the tiers (move 2), then play back and write the outputs (§7).

## 3. Question bank

| # | Question | Scope |
|---|---|---|
| R1 | What is the worst realistic failure here: a confidentiality breach, a wrong filing, a fabricated authority, an independence breach? | [U] |
| R2 | Which outputs leave the firm, and who outside relies on them? | [all] |
| R3 | For this kind of work, who checks the AI-assisted output today, and what exactly do they check? | [T] |
| R4 | If this output reached the client unverified, which of our controls would catch it? | [T/U] |
| R5 | Where would an agent or automation act without a person watching, and what could it change? | [U/O] |

## 4. Expert moves

1. **Set the standard as "same diligence as if AI were not involved", with the user accountable.** Firms told PCAOB
   staff that reviewers apply the same diligence as when AI was not involved [PCAOB-GENAI-2024, pp.4-5]; ABA Opinion
   512 says the lawyer is fully responsible whatever level of review is chosen [ABA-OP512-2024].
2. **Replay public incidents as scenario tests.** Counsel and firm were sanctioned $5,000 for submitting non-existent
   cases generated by a chatbot [SDNY-AVIANCA-2023]; a consultancy agreed to repay the final instalment of a government
   report contract after errors including incorrect references, having disclosed generative AI use, while not saying
   AI caused the errors [GUARDIAN-DELOITTE-2025].
3. **Test before you trust, on the firm's own samples**, before a tool enters tier-3 or tier-4 work and after model
   changes. Model-risk guidance applies validation to vendor models and expects "effective challenge" by objective,
   informed parties [FRB-SR117-2011].
4. **Give agents least privilege, activity logs, a stop switch, an inventory entry, and a list of actions that always
   pause for a person** (irreversible, sensitive or high-value). OWASP lists excessive agency among LLM application
   risks [OWASP-LLM-2025] (`../../transformation-advisor/references/method/plan-and-control.md` §3.4).

## 5. Default tiers and decision rules

**Default tiers (advisor default; adjust with the user):**

| Tier | Typical uses | Reviewer and check | Record (step 4) |
|---|---|---|---|
| `tier-1` Internal, low consequence | Admin, internal drafts, brainstorming on public or firm-internal data | The user checks before use | Tool logs only |
| `tier-2` Informs professional work | Research notes, analysis, first drafts a professional then uses | The user verifies sources and figures; normal review unchanged | Light: tool used and what was checked |
| `tier-3` Client-facing or relied on | Deliverables, advice, client communications, anything leaving the firm | A named qualified reviewer checks facts, figures and every citation against its source before release | Input description, how verified, who reviewed [CPAI-2026] |
| `tier-4` Regulated or high-impact | Attest procedures and evidence, signed returns and filings, court submissions, decisions about people, agents acting on client data or outside the firm | Use-case approval record before use; test results on firm samples; written reviewer instructions; regime steps (step 5) | Tier 3 plus tool and model version, configuration, why use was appropriate, approval, how output informed the conclusion |

**Ladder rule (advisor default):** each move up the ladder (assist → augment → automate → delegate) raises the tier by
at least one level until test evidence supports lowering it. `delegate` is always `tier-4` and must pass the five
delegation gates in `../../transformation-advisor/references/method/onboarding.md` §5.

**Pattern map (advisor default).** For each pattern in use, take checkpoints and failure modes from the library §3
and record: ladder rung, minimum tier, what the reviewer owns, failure to watch. Minimum tiers: `tier-2` for research,
knowledge and triage patterns that stay inside; `tier-3` once output reaches a client or court, or the pattern runs
automatically (document decisions, reconciliations, bulk changes, service agents); `tier-4` for attest or filing
decisions, full-population testing in attest work, monitoring patterns that act, and `end-to-end-case-agent`.

**Decision rules**
- A tier is set for the use, not the tool; `max_risk_tier` on the catalog entry is a ceiling.
- Recruitment, decisions on terms of work, task allocation on behaviour or traits, and monitoring or evaluating staff
  are `tier-4` (advisor default): the EU AI Act's Annex III lists them [AIACT-EXPL-2026, Annex III point 4], with
  high-risk obligations from 2 December 2027 under Regulation (EU) 2026/1744 [EU-OMNIBUS-2026]; re-verify dates.
- Agents follow move 4; a `workflow-automation` logs each run and names its human checkpoint.

## 6. Worked example

Illustrative. An audit practice puts research and memo drafting at `tier-2` (every cited standard checked at source)
and performing audit procedures with AI at `tier-4`, not permitted until approved; the tier-2 use is the alternative.

## 7. Output

Write section 4 of `overlay/policy.md`; set `risk_tiers` in the frontmatter. Set `max_risk_tier` on each entry in
`overlay/tool-catalog.yaml`. Add review lines to `overlay/guardrails.md`. Set `step_completed: 3`, `next_step: 4`.
